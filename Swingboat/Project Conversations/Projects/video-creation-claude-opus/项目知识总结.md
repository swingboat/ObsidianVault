# video-creation-claude-opus · 项目知识总结

本次会话证据讲清楚了一条可复用的路线：**参考作品 → 拆解技术，逐项核对本机条件 → 实测单帧耗时 → 做 10 秒验证片 → 设检查点逐步收敛 → 用混合引擎出片 → 管理仓库和缓存。**

已落地并有文件佐证的成果是 `paper-whale`：一条 10 秒的验证短片。

- 制作方式：Python 驱动 Blender 5.2；1.6 万页纸用 NumPy 模拟，聚成一头座头鲸；声音全部用代码合成；最后用 ffmpeg 调色、合成。
- 制作耗时约 1.5 小时，渲染约 40 分钟。
- 成片没有在本轮观看或试听，声音在会话中也只做过电平检查。

其他 14 个作品目录没有相应的制作会话。它们的经验见 [[Video Creation/Projects/video-creation-claude-opus/项目索引|视频制作项目索引]]（上一次 capture 的产物），本页不重复。

## 二、知识点

### EEVEE 与 Cycles 如何分工 [S01-T01]

- **原理**：EEVEE 用光栅化加屏幕空间近似，每帧秒级；Cycles 是物理路径追踪，每帧几十秒到几分钟。
- **材质共用**：两者用同一套着色节点，大多数场景切换引擎不用改材质。在脚本里改 `scene.render.engine = 'BLENDER_EEVEE' / 'CYCLES'` 即可。
- **EEVEE 的弱点**：体积光（光柱）精度低，可能有分层或闪烁；半透明和次表面散射只是近似；间接光只算画面里看得见的部分。
- **本项目的规则**：
  - 预览一律用 EEVEE；
  - 快速运动、带运动模糊的镜头，可以直接用 EEVEE 出终版；
  - 静态微距和光影镜头用 Cycles。

### 为什么用 PC2 缓存，而不是 Blender 粒子系统（F02、F03）

- 所有动画都写成「时间 → 顶点」的纯函数。先用 NumPy 算出每一帧的全部顶点（16000 页 × 6 个顶点），写成 PC2 文件，再用 Mesh Cache 修改器回放。
- 拓扑不变：每页 3×2 个顶点，可以沿长边中线折弯。Blender 在子帧之间线性插值，所以 Cycles 和 EEVEE 都能做形变运动模糊。
- 原作者也没用粒子系统，而是自己写的模拟 [S01-T00]。好处是：
  - 每页纸的行为可以完全控制；
  - 用固定的随机种子，结果每次都一样；
  - 音频还能读取同一份每帧统计（`events.json`）。
- 边界：缓存约 200 MB，修改动画后需要重新计算。

### Git 相关知识点 [S01-T04、S01-T05]（F05 已核对）

- **GitHub 单文件上限 100 MB**：超过上限的文件需要用 Git LFS，或者排除在仓库外，并写明从哪里重新下载。
- **`.gitignore` 的锚定规则**：
  - 模式中间只要出现 `/`，就相对 `.gitignore` 所在目录匹配。所以 `reference/frames/` 只匹配根目录下的 `reference/frames/`；
  - 要匹配任意层级，写 `**/reference/frames/`；
  - 已经被跟踪的文件，加入忽略规则后不会自动移出仓库，还要从索引中删除。会话中删除了 10 张参考帧，在 `02a6fcc` 中确认。
- **不要用整目录规则排除交付物**：`out/` 规则会连字幕、封面、发布文案一起排除。视频已经按扩展名排除，所以删掉了 `out/` 规则，让文本交付物进入仓库。
- **一台机器多个 GitHub 账号**：只在当前仓库设置 `core.sshCommand`，用 `-F /dev/null -i <专用密钥> -o IdentitiesOnly=yes` 指定这个仓库专用的密钥。不改全局 `~/.ssh/config`，也不影响其他仓库。

## 三、算法

### 1. 纸群的「流管槽位」模拟（F03）

- **输入**：页数 N = 16000、随机种子 7、局部时间 t。
- **输出**：每帧 N×6×3 个顶点（float32），以及给音频用的统计数据。
- **步骤**：
  1. **固定属性**：每页纸有队伍顺序 `u ∈ [0,1]`、截面槽位 `(r = sqrt(U), θ)`（在圆盘内均匀分布）、翻滚轴和相位、折弯频率，以及在鲸身上的次序 `k`。
  2. **路径**：入口是一条三次贝塞尔曲线，接一段竖直的螺旋回环。先密采样 400 个点，再用 `np.interp` 按弧长重新参数化，保证匀速。螺旋的半径随弧长渐变，衔接处不会跳变。
  3. **队伍位置**：`s_i(t) = v·(t + 0.3 − 3.0·u_i)`，v = 6 m/s，所以排头先到、排尾后到。
  4. **截面偏移**：用切线和上方向构造局部坐标系 `N = normalize(T × up)`、`B = N × T`。在这个坐标系里按 `R_tube·r·(cosθ·N + sinθ·B)` 偏移。管半径 ∝ `sqrt(sin(πu))`，所以队伍两头细、中间粗。
  5. **噪声**：每页纸自身的正弦抖动，加上 3 个群体波分量 `Σ 0.5·sin(k_j·p + w_j t)·d_j`，形成椋鸟群那样的波浪。
- 另有 5% 的「散页」，始终不入队，用来增加层次。

### 2. 依次聚形（F03）

- 每页的开始时间：`tc_i = 3.6 + 1.2·k_i + 0.2·rand`，时长 1.1 s，进度 `e = smootherstep((t − tc)/D)`。
- 位置：`P = lerp(S_i, W_i, e) + sin(πe)·arc_i`。`arc_i` 是一个随机的弧形偏移，让纸页沿曲线飞到位，而不是走直线。
- 朝向：在翻滚姿态和目标姿态之间用四元数 `slerp` 插值，折弯幅度乘 `(1 − 0.85e)`，到位后基本停止折弯。
- 效果：按 k 从鲸头到尾巴依次到位，观众能看到鲸被「画」出来。

### 3. 参数化鲸的目标点云（F03）

- 身体半径：`r(s) = 1.3·s^0.4·(1−s)^1.2 / 0.406`。截面是椭圆，腹部略压扁。
- 鳍：两只长胸鳍（座头鲸辨识度最高的部分）、一个三角背鳍，以及后缘呈 M 形缺口的尾鳍。
- 采样：身体约 78%，按周长加权采样；胸鳍 10%，尾鳍 10%，背鳍 2%。每个点沿法向随机偏移 ±0.06 m，让纸页叠出鳞片般的厚度。
- 游动：中心线的 z 偏移为 `A(t)·s²·sin(2.2t − 3.5s)`，所以越靠尾部摆得越大。
- 复杂度：每帧 O(N) 的向量化计算。会话和文档都没有记录单独的模拟耗时。

### 4. 代码合成声音（F04）

- **纸沙声**：几十层带通噪声（中心频率 1.5–6 kHz），每层用 8–25 Hz 的颗粒包络调制。
  - 总响度跟随纸群速度，左右声像跟随纸群重心的 x 坐标；
  - 在镜头切点前 0.25 s 先淡入（J-cut）。
- **聚形的「呼」声**：150–600 Hz 的低频噪声，做上扬扫频。
- **加法合成钢琴**：
  - 每个音 12 个泛音，非谐性 B = 0.0004，每个泛音单独做指数衰减；
  - 加 4 ms 的击弦噪声；
  - 两根弦相差 ±0.6 音分，产生拍频。
- **混响**：用指数衰减的噪声生成冲激响应（RT60 约 3.2 s），与信号卷积；左右声道去相关。
- **混音**：母线用 tanh 软限幅。会话中测得 −15.7 LUFS，没有试听 [S01-T02]。

## 四、最佳实践（来自本项目的真实经验）

## 五、决策与演进

1. **可行性评估**：结论是能做；难点在渲染时间和镜头审美，不在技术 [S01-T00]。
2. **题材**：保留原片的「深夜图书馆 + 纸页」，最后聚成的动物从狐狸、鹰、乌龟换成鲸，方便和原片对比，也不逐镜头照搬（F01）。
3. **渲染方案**：
   - 一开始考虑全部用 Cycles，降低采样后分批过夜渲染 [S01-T00]；
   - 讲完 EEVEE 后，改为预览用 EEVEE、成片按镜头混合 [S01-T01]；
   - 最终是镜头 1 用 Cycles、镜头 2 用 EEVEE（F01）。
4. **路径形状**：水平圆环从低机位看只是一个扁平的光团，改成正对镜头、后仰 20° 的竖直螺旋回环（F01、F03，「实测后修订」）。
5. **鲸身上的暗斑**：
   - 原因：胸鳍根部的纸页埋在身体里，而且一半纸页背对光；
   - 改法：去掉根部那 12%，鳍上纸页的法向统一朝向镜头一侧；加一盏用 light linking 只照纸群的 key 光；法向加随机散布（F01）。
6. **镜头 1 的噪点和耗时**：
   - 主角页单独用透光 0.12 的纸材质；
   - 给体积雾的 `hide_render` 打关键帧，镜头 1 不渲染体积雾；
   - Cycles 改为 128 采样、自适应阈值 0.01、直接光 clamp 8；
   - 单帧耗时从 38 s 降到 28 s，最终平均 22 s（F01）。
7. **`.gitignore`**：首次提交时，`out/` 规则误排除了文本交付物，`reference/frames/` 规则只匹配根目录。在 `02a6fcc` 中修正：去掉 `out/` 规则，改为 `**/reference/frames/`（F05 已核对）。
8. **尚未解决**：
   - 鲸身近看偏平，有拼贴感；
   - 钢琴音色偏电子；
   - EEVEE 镜头的光柱精度不够。
   
   这些都是助手对比原作后的自评，用户没有给出验收意见 [S01-T02]。
