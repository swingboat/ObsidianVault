## 统一制作管线

40 部视频用的是同一条管线，没有用到 3D 引擎、生成式图像或视频模型。每部视频都是复制上一部的目录后改出来的。

| 步骤 | 输入 → 输出 | 入口 | 要点 |
| --- | --- | --- | --- |
| 1. 文案 | 需求 / geo-story-studio build → `script.json` | `script.json` | 包含 `voice`/`voices`（各角色的 name、rate、pitch）、`curriculum`、`numbers`/`source`、`based_on`；后期作品还把审校边界写进 `based_on` |
| 2. 配音 | `script.json` → `build/narration.wav`、`build/timeline.json`、`out/*.srt` | `tts.py` | edge-tts 神经语音，`boundary="WordBoundary"` 输出逐词时间；替换 `WSS_URL`；遇到 429 等待重试；以 `sha1(voice\|rate\|pitch\|text)` 为键缓存到 `build/tts_cache/`；ffmpeg 用 `adelay` → `amix` → `loudnorm=I=-16:TP=-1.5:LRA=11` 混音 |
| 3. 画面 | `timeline.json` → 逐帧 RGBA | `render.mjs` + `lib.mjs` + `scenes-*.mjs` | 场景模块各自导出 `scenes`/`events`；动画锚定在“某个词说出的时刻”；`--still t1 t2` 导出预览帧 |
| 4. 声音设计 | 事件表 → 音乐 / 音效 | `audio.mjs` | 程序合成（Karplus–Strong 拨弦等），不用外部音频素材；`audio.mjs` 在大量作品中逐字节相同 |
| 5. 合成 | 帧管道 + 音轨 → `out/*.mp4` | `render.mjs` | H.264 + AAC；角标 logo（`LOGO_BOX`，裁掉透明边），后期作品有片尾品牌卡 |

一般流程：先定 `script.json` 并经用户确认，再跑 `.venv/bin/python tts.py`，然后 `node render.mjs --still …` 抽查帧，最后 `node render.mjs` 出成片。本次没有执行这些命令。

## 跨作品制作经验

以下内容都从项目文件归纳而来，括号里是依据。会话内容读不到，所以下面没有一条是用户验收过的结论。

1. **只读核对时，TTS 缓存可以当作改稿记录。** 把 `script.json` 每句按 `sha1(voice|rate|pitch|text)` 重新算哈希，与 `build/tts_cache` 比对，就能看出哪些句子改过、语速试过几档，例如 `meteor-journey` 改过 8 段，`afternoon-heat` 把“教材的说法”改成了“规范的说法”。没有会话记录时，这是最可靠的迭代证据。
2. **以词为锚点。** 动画、数字卡和字幕的时刻都用 `at(词)` 这类 WordBoundary 时间来定，见各片 `lib.mjs`。改了文案后重新跑 TTS，画面会自动重新对齐，不需要按字数估算。
3. **示意图要用公式算，不要手摆。** 风向三力平衡（`wind-forces`）、等压面偏移和环流反转（`thermal-circulation`、`sea-land-breeze`）、气压 `1013·exp(−z/8000)`（`air-pressure`）、光束宽 `w/sin h`（`sun-angle`），都是由公式得出的。这样能从代码层面核对“箭头方向对不对”，符合 §6 的制图规范。
4. **把科学审校边界写进代码。** 例如：
   - 水汽画成虚线空心圆，不画成小水滴；
   - 盐点数量恒定，克数随口播滚动；
   - 紫外线随臭氧衰减但不归零；
   - 温度轴不标 ℃；
   - 熔融光点只占约 16% 的格子。
   
   `geologic-day` 和 `meteor-annual` 更进一步，用 `validate.mjs` 把口径变成可执行的检查。
5. **复制模板会把旧东西一起带过来。** 例如：
   - `tts.py` 的 docstring 里还写着“Neptune”；
   - 用法注释指向别的视频；
   - `crumble`、`sizzle` 等用不到的音效；
   - `TAIL` 注释说为品牌卡留了时长，代码里却没有品牌卡。
   
   复制后要清理注释、无用的部件和配色键。
6. **至少有两套代码模板。** 两者在字幕位置（1500/1560）、配乐音量、转场时长、品牌卡写法和每个声音的音频滤镜上有差异，见 batch F/H 各片 `render.mjs` 的 diff。改进一套时要同时对齐另一套，比如 `outro.tagline` 在 B 模板里就没有进入时间轴。
7. **推荐版是同一套代码加一个 `--rec` 开关，口径要同步。** `plateau-basin-sunlight` 完整版用的是 2014 年的阈值，推荐版用的是 2022 年公报的数据；推荐版也漏了品牌卡。
8. **安装说明不完整。** `fonts.py` 依赖 `fontTools`，但 README 和 AGENTS 的安装命令里没有写。`@napi-rs/canvas` 的锁定版本从 1.0.11 → 1.0.13 → 1.1.0 先后变化过。
9. **`based_on` 里有本机绝对路径。** 多部作品的 `script.json` 用绝对路径记录源 build，换一台机器就失效，建议改成相对于 geo-story-studio 的路径。
10. **节奏。** 10-31 一天做了 13 部，每部约 20–55 分钟（按会话创建时间到成片 mtime 推算，不是计时记录）。产量依靠模板复制和 §3 的分文件写法；“写一组、验一组”的 `--still` 拼图检查只在规则里写了，本次没有找到检查记录。
