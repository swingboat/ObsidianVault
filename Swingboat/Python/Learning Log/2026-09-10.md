# Python 学习记录 · 2026-09-10

## 11:04 QR Code 的作用与 Python SVG 渲染

### 我的问题

二维码在微信扫码登录中起什么作用，为什么服务器已经拿到扫码链接，页面却可能不显示二维码？

### 核心结论

QR Code 是一种把文本、URL 等载荷编码成二维图案的表示方式；手机扫码后解码得到的仍是原始载荷。Python 的 `qrcode` 包负责把载荷渲染成可显示的 PNG 或 SVG，但它不负责微信认证协议本身。

### 工作原理

以扫码登录为例，完整流程可以拆成四层：

1. 服务端向微信申请一次性的扫码载荷，通常是带有会话标识的 URL。
2. Python 使用 `qrcode` 将该字符串编码为二维码图案；选择 `SvgPathImage` 时，结果是浏览器可直接显示的 SVG。
3. 手机微信扫描图案，解析出 URL，并由用户在手机端确认授权。
4. 服务端持续轮询登录状态。

因此，“页面显示了原始 URL，却没有二维码”通常表示认证服务已经返回载荷，但本地缺少二维码渲染依赖。此时协议前半段是通的，失败发生在展示层。合理的降级策略是显示原始载荷，而不是把渲染失败误报为微信连接失败。

### 最小示例

```python
import qrcode
import qrcode.image.svg

payload = "https://example.com/login?session=temporary-id"
image = qrcode.make(
    payload,
    image_factory=qrcode.image.svg.SvgPathImage,
)
svg_bytes = image.to_string()

print(svg_bytes[:40])
```

该示例只是把字符串编码为 SVG，不会验证 URL，也不会执行登录。

### 容易踩坑

- `ModuleNotFoundError: No module named 'qrcode'` 说明当前运行服务的 Python 环境缺少包；应把依赖安装进同一个虚拟环境，而不是系统 Python。
- 有些虚拟环境没有 `pip` 模块，可以使用 `uv pip install --python .venv/bin/python qrcode` 安装到指定解释器。
- 二维码图案不是凭证本身的安全边界：一次性扫码 URL 仍可能包含短期会话标识，不应长期保存或公开分享。
- 旧二维码通常会过期；补装依赖或重启服务后，应重新申请二维码，而不是继续使用旧载荷。

### 在当前项目中的应用

DeepTutor 的 `deeptutor/services/partners/weixin_onboarding.py` 从微信取得扫码载荷后，使用 `qrcode.image.svg.SvgPathImage` 生成 SVG。若无法导入 `qrcode`，代码会返回原始载荷供界面显示，因此用户会看到 URL 而不是空白区域。
