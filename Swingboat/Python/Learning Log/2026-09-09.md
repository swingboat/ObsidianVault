# Python 学习记录 · 2026-09-09

## 10:25 Python HTTPS 证书信任与 truststore

### 我的问题

Python 访问 HTTPS 服务时为什么会出现证书验证错误，`truststore` 在其中解决了什么问题？

### 核心结论

HTTPS 客户端不是简单判断“服务器有没有证书”，而是要验证服务器证书能否沿证书链追溯到本机信任的根证书，并确认域名、有效期等信息。`truststore` 让 Python 的 TLS 连接使用操作系统原生证书库，可继承系统管理员安装的企业根证书等信任配置。

### 工作原理

TLS 握手时，服务器通常发送站点证书和中间证书。客户端使用信任库中的根 CA 验证整条证书链；链不完整、根 CA 不受信任、证书过期、访问域名不匹配或系统时间错误，都可能触发 `CERTIFICATE_VERIFY_FAILED`。

Python 的 `ssl` 基于 OpenSSL。不同 HTTP 客户端可能使用系统默认 CA 路径、独立的 CA 包（例如 `certifi`），或者调用者明确传入的 `SSLContext`。因此，“浏览器能打开，但 Python 请求失败”并不矛盾：二者可能使用了不同的信任来源。

`truststore` 提供兼容 `ssl.SSLContext` 的系统信任库接口。应用程序可以显式创建并传递上下文；`inject_into_ssl()` 会全局修改后续 `ssl.SSLContext` 的行为，适合应用启动阶段，不适合由可复用库擅自调用。

### 最小示例

```python
import ssl
import urllib.request

import truststore

context = truststore.SSLContext(ssl.PROTOCOL_TLS_CLIENT)

with urllib.request.urlopen(
    "https://example.com",
    context=context,
    timeout=10,
) as response:
    print(response.status)
```

### 容易踩坑

- 不要把关闭证书验证当作正式修复；它会使客户端失去服务器身份校验，容易受到中间人攻击。
- CA 证书用于验证对方身份，客户端证书用于双向 TLS 身份认证，两者用途不同。
- 企业代理或 HTTPS 检查设备会重新签发站点证书；若其根 CA 只安装在系统证书库，而 Python 客户端只读取独立 CA 包，就可能验证失败。
- `SSL_CERT_FILE`、`REQUESTS_CA_BUNDLE`、自定义 `verify` 路径和 `SSLContext` 的支持范围取决于具体客户端库，不能假定对所有 Python 网络库都同样生效。
- 使用 `truststore` 只能解决“信任来源”问题；域名不匹配、证书过期、服务器漏发中间证书等问题仍需分别修复。
